# 旅行电量表 · Travel Power Gazette

**把旅行中的精力当成一块电池来记账。** 每件事消耗多少、回血多少，当天还剩几格电——勾选完即刻结算。

🔗 **在线体验**：<https://gavinduan.github.io/travel-power-app/>

零构建、纯静态，打开即用，不装依赖、不注册账号、不上传任何数据。

---

## 一、为什么做这个

旅行攻略几乎都在教人怎么把行程排得更满，却没有人计算过：按这个安排，到第三天你还能剩多少精力。

真正毁掉一趟旅行的，往往不是天气或预算，而是走到第三个景点时，那点所剩无几的兴致。早上七点在机场还能规划三条街，下午四点站在路边，只想找一张能坐的长椅。

这个项目要解决的问题很具体：**把旅行里看不见的精力消耗，变成一张可以提前看清的账。**

它把「赶早班机」「在陌生城市找路」「博物馆站两小时」「网红店排队」这些日常支出，和「午睡二十分钟」「洗个热水澡」「看日落发呆」这些回血项，都标上了电量点数。你只要勾选，右侧面板就实时结算，告诉你今天大概能撑到几点、什么时候该主动关机。

视觉上选择报纸特刊而不是常见的旅行 App 界面——报纸天生适合「记账」和「报道」这件事：三栏正文、双线分隔、铜版画插画、分类广告。配图不提供答案，只负责说出真相：一位疲惫的旅人坐在长椅上，头顶悬着一枚只剩一格的电池；一条没有测过坡度的山路。

说到底，它是一个**反攻略**工具。它不教你怎么塞满一天，而是让你有理由在下午三点坦然地坐着什么都不做。

因为回血不是行程的间隙，回血就是行程本身。

## 二、功能亮点

| # | 能力 | 说明 |
|---|---|---|
| 1 | 精力当电量记账 | 勾选条目即结算，右侧电量面板实时更新剩余百分比与判定文案 |
| 2 | 双向词库，数值可改 | 内置 20 条体感条目，负数为支出、正数为回血，全部可增删改 |
| 3 | 四种模板一键套用 | 标准观光日 / 硬核徒步日 / 城市散策日 / 带娃出行日，套用后自动生成整套条目 |
| 4 | 报表与低电预警 | 自动算出最耗电的支出、最有效的回血、平均余量、低于 20% 的低电日清单 |
| 5 | 数据自己拿着 | 全部存在本机浏览器；支持导出 / 导入 JSON，换浏览器、换设备不丢账 |

## 三、五个视图

| 视图 | 用途 |
|---|---|
| **01 行程** | 建档：名称、目的地、起止日期、每日初始电量（默认 100）。卡片显示平均余量，可删除行程（二次确认）。 |
| **02 每日记账** | 按天记支出与回血，实时显示剩余电量、当天电量曲线、当日备注。常用条目点选即入账。 |
| **03 行程模板** | 把典型的一天存成模板，套用到任意一天，自动生成整套条目。内置 4 个模板。 |
| **04 统计报表** | 平均余量、总支出 / 总回血、低电日警告、逐日电量柱状图、Top 消耗与 Top 回血排行。可导出 PDF 报告。 |
| **05 支出词库** | 记账时可选项的来源。负数为支出，正数为回血。内置 20 条，可自行增删。 |

### 电量是怎么算的

- 当天剩余电量 = 该行程设定的初始电量（默认 100）+ 当天所有条目点数之和；
- 结果钳制在 `0–100`，不会透支成负数，也不会超过满电；
- 结算与勾选顺序无关（纯求和）；只有曲线图会按条目的时间排序来画走势；
- 剩余电量给出五档判定：

| 剩余 | 判定 |
|---|---|
| ≥ 75% | 满血。你甚至有条件在机场买一杯很贵的咖啡。 |
| ≥ 55% | 状态不错。还可以再走一条没在计划里的街。 |
| ≥ 40% | 尚可。建议找一张椅子坐二十分钟，别硬撑到天黑。 |
| ≥ 20% | 低电。任何需要排队的项目，都请礼貌地放弃。 |
| < 20% | 自动关机。回酒店，洗个澡，明天再说。 |

报表里的「低电日」统计的正是收于 20% 以下的天数，并会点出当天最主要的消耗项。

## 四、使用场景

- **出行前做精力预算**：给行程建档，套用模板预演每天电量。如果发现第三天必然关机，就把景点往前挪。
- **旅途中实时记账**：每走进一个景点、排完一次队就记一笔。看到低于 20% 就取消后续项目，主动回酒店。
- **多人同行对齐节奏**：把当天电量面板给同伴看。「还剩 18%」比「我有点累了」更容易被理解。
- **回程后复盘**：用统计报表找出此行最耗电的项目，下次同类型旅行直接避开，或者提前预留回血时间。

快捷键：`Ctrl / Cmd + N` 跳到行程视图；`Esc` 关闭导入弹窗。

## 五、数据与备份

**所有数据只保存在你自己浏览器的 localStorage 里**（键名 `travel-power-gazette-v1`），不上传到任何服务器，也没有账号体系。

这也意味着：**清浏览器数据、换浏览器、换设备都会丢账。**

侧栏提供四个数据入口：

| 入口 | 作用 |
|---|---|
| 数据保存在本浏览器 | 显示当前数据的具体存储位置 |
| 导出全部数据 (JSON) | 导出一份完整备份文件，建议定期做 |
| 导入数据 (JSON) | 从备份恢复，可选择「合并到现有数据」或「整体替换」 |
| 撤销上次导入 | 恢复到本次导入之前的状态（仅在一次导入后出现） |

### 关于导入的两点说明

**合并模式**按名称与 id 对齐词条，冲突时自动重映射引用，所以模板项不会指向不存在的词条；同名同起止日期的行程会被识别为同一条，不会重复堆积。**替换模式**则完全以文件为准——文件里没有的词库和模板就是没有，不会被默认值补回来。

**每次导入前，当前数据会自动存一份快照**，所以选错模式也能一键撤回。这份快照和「读取失败时的原始数据备份」是两处独立的存储，互不覆盖。

### 意外情况的兜底

- 本地数据损坏、解析失败时：**不会用空数据覆盖你原来的记录**。页面顶部会出现告警条，原始数据已单独留存，可一键导出；你也可以选择放弃并重新开始。
- 写入失败（如存储空间已满）时：会弹出提示告诉你存不上、右侧状态变成「保存失败」，而不是让你以为记上了、其实全丢。此时请先导出 JSON，再腾空间。
- 关标签页或切到后台时：会立即补写一次，避免最后一次改动丢失。

## 六、本地运行

```bash
# 任选其一
python3 -m http.server 8000
npx serve .
```

然后打开 <http://127.0.0.1:8000>。

直接双击 `index.html` 也能用，但建议走 http——字体与 PDF 组件的跨域行为更稳定。

## 七、技术说明

- **无框架、无构建**：`index.html` + `styles.css` + `app.js` 三个文件，改完刷新即生效。
- **图表手写内联 SVG**：柱状图、电量曲线都是直接拼 SVG，不引图表库。
- **PDF 导出**用 [html2pdf.js](https://github.com/eKoopmans/html2pdf.js)（CDN 引入），后台生成独立排版的报告文档，不走系统打印对话框；另有配套的打印样式（`@media print`）用于浏览器直接打印。
- **日期处理按本地时区**：统一用 `localISO()` 而非 `toISOString()`，避免 UTC 偏移导致的「少一天」；纯日期字符串按 `T00:00:00` 解析，避免西半球退一天。
- **字体走 Google Fonts CDN**（Noto Serif SC + Playfair Display），页面已做 `preconnect`。网络受限时字体会回退到系统衬线体，版式不破。
- **`store` 留了一层 `window.api` 兜底**，用于兼容早期的 Electron 版本。
- **兼容性**：现代常青浏览器（Chrome / Edge / Firefox / Safari）。未做 IE 适配。
